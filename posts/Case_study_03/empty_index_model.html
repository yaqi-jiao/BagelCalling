case

when I read the code and run scripts from cloned SIR model for my project, I noticed that all outputs were automatically organized into a structured directory hierarchy:

results /
    simulated_protein /
        protein_type /
            tune_folder /
                epicenter_region /
                    model_name_timestamp

I really liked this design for two reasons:

  1. model details are automatically encoded into nested folders and filenames;
  2. each run includes a timestamp, so repeated runs with the same configuration will not overwrite previous results.

I removed some unrelated prints and commands below to make the core logic easier to read.

params.py

def get_proj_path():
    """
    Dynamically determine the project path based on the current script's location.
    """

    current_file_dir = os.path.dirname(os.path.abspath(__file__))
    script_dir = os.path.abspath(os.path.join(current_file_dir, os.pardir))
    
    # Set the project path to the grandparent folder (uncomment if needed)
    proj_path = os.path.abspath(os.path.join(script_dir, os.pardir)) # set to grandparent folder
    return [script_dir, proj_path]

   
def make_output_dir(args, proj_path, script_path, hypertune):
    """
    Create the output directory based on model arguments.
    """
    
    # Generate output date and time
    output_date_time = datetime.now().strftime("%Y%m%d_%H%M%S")
    print("Program starts at {}".format(datetime.strptime(output_date_time, "%Y%m%d_%H%M%S").strftime("%d-%m-%Y %H:%M:%S")))
    if not args.output_date_time: args.output_date_time=output_date_time

    # Define paths
    args.proj_path = proj_path
    args.script_path = script_path
    args.input_path = os.path.join(proj_path, "data")
    
    # Determine folder structure based on hypertuning and epicenter
    tune_folder = "hypertune" if hypertune else ""
    epi = "precuneus" if "precuneus" in args.epicenter_list else ("entorhinal" if "entorhinal" in args.epicenter_list else "")
    if "null_model" in args.model_name: tune_folder = "Null_models"

    # Add connectivity and regional vulnerability to model_name
    if args.SC and args.SC not in args.model_name: args.model_name += "_" + args.SC
    for var in ["spread_var", "synthesis_var", "misfold_var", "clearance_nor_var", "clearance_mis_var"]:
        if isinstance(getattr(args, var), str):
            regional_name = var.split("_")[0] + "-" + getattr(args, var)
            if regional_name not in args.model_name:
                args.model_name += "_" + regional_name

    # Construct output path
    args.output_path = os.path.join(proj_path, "results", args.simulated_protein, args.protein_type, tune_folder, epi, args.model_name + "_" + args.output_date_time)

    # Create output directory
    os.makedirs(args.output_path, exist_ok=True)

    return args

study

1. Minimal os.path background

This project mainly relies on a few core os.path utilities:

os.path.abspath(__file__)  # absolute path of current file
os.pardir  # parent directory ("..")
os.path.join(a, b, c)  # safely combine paths 
os.makedirs(path, exist_ok=True)

2. Starting point: locating the project root

in get_proj_path(), the project root path is dynamically determined from the current script location.

current_file_dir = os.path.dirname(os.path.abspath(__file__))
script_dir = os.path.abspath(os.path.join(current_file_dir, os.pardir))

proj_path = os.path.abspath(os.path.join(script_dir, os.pardir))

The resulting paths are later stored into args:

args.proj_path = proj_path
args.script_path = script_path
args.input_path = os.path.join(proj_path, "data")

After this step, other functions can reuse these paths without recomputing them.

3. Build output path from arguments

In make_output_dir(), the output path is NOT hardcoded. Instead, it is constructed dynamically from multiple variables.

This design automatically encodes:

  • experiment type
  • protein type
  • tuning mode
  • epicenter region
  • model configuration
  • timestamp

into the folder structure.

Also notice, immediately after constructing the path, the directory is created:

os.makedirs(args.output_path, exist_ok=True)

This guarantees that later save operations will not fail because of missing folders.

4. Pass output_path into classes and functions

The constructed output path is passed into TuningResultsTracker through args.

def __init__(self, args, param_combinations):

    Initialize the TuningResultsTracker object with given arguments and hyperparameter combinations.

    self.param_combinations = param_combinations
    
    # Initialize storage structures
    self.simulated_data = {"simulation":[], "Rmis":[]}

After this initialization step, all saving and plotting functions can reuse the same directory through self.output_path.

This avoids repeatedly rebuilding paths in different parts of the code.

5. Separate path definition from save logic

A usefule design pattern in this project is separating:

  • where results should be saved
  • how results should be saved

The directory structure is defined once in make_output_dir(), while the actual save operations happen later inside methods like:

  • save()
  • print_and_plot_best()
  • scatter_plot_across_time()

for example, .npy and .pkl files share similar save logic, we dont need to plot, so save() is enough, while figures require dedicated plotting functions before saving

np.save(os.path.join(self.output_path,'Y_observed.npy'), self.y)
for result_type in self.simulated_data:
        # for npy files
        np.save(f, np.array(self.simulated_data[result_type], dtype=np.float16))
        # for pkl files
        pickle.dump(self.r_dict[result_type], f, protocol=4)

6. Add timestamps to avoid overwriting results

The timestamp is generated once, and appended later when constructing the final output path:

output_date_time = datetime.now().strftime("%Y%m%d_%H%M%S")
...
args.output_path = os.path.join(proj_path, "results", args.simulated_protein, args.protein_type, tune_folder, epi, args.model_name + "_" + args.output_date_time)

This makes repeated runs reproducible and prevents accidental overwriting. And notice, timestamp is being appended as variable.

takeaway

  1. If your project structure is organized, first determine the project root with os.path or pathlib, then construct all other paths relative to it.
  2. Separate:
    1. path consruction
    2. directory creation
    3. actual saving logic
  3. adding timestamps into filenames or directories helps avoid overwriting previous runs
  4. pathlib provides a cleaner and more object-oriented way to work with paths compared with raw string concatenation.
